# Триаж входящих заявок: n8n + Claude Haiku 4.5

Демо автоматизации для вымышленной сервисной компании (ремонт и аренда оборудования,
уборка, консультации). Заявка свободным текстом превращается в проверенный JSON,
сохраняется и появляется на публичной доске. Расход на LLM ограничен дневным бюджетом,
частота запросов — лимитами, контакты в тексте маскируются.

```
заявка (форма или POST /webhook/triage)
  -> маскирование телефонов, email, карт, @ников
  -> cost guard: 5 заявок/час с адреса, 60/час всего, $0.50 в день
  -> Claude Haiku 4.5, structured outputs по JSON-схеме
     (нет ключа API -> mock-заглушка по ключевым словам, mode=mock)
  -> проверка ответа, 1 повтор, потом needs_human=true
  -> Data Table n8n -> доска GET /webhook/board -> Telegram (нода выключена)
```

Результат разбора:

```json
{
  "category": "repair | rental | cleaning | consultation | complaint | spam | other",
  "urgency": "low | normal | high",
  "city": "Казань",
  "budget_rub": 15000,
  "summary": "до 20 слов",
  "next_step": "одна фраза менеджеру",
  "needs_human": false,
  "confidence": 0.92
}
```

## Что проверено и что нет

Цифры ниже взяты из файлов `evals/results/`, других замеров нет.

**Настоящий Claude не вызывался ни разу: ключа API пока нет.** Качество классификации LLM
не измерено. Все прогоны шли в mock-режиме или против локальной заглушки API.

| Прогон | Дата (UTC) | Что показал |
|---|---|---|
| `2026-10-05-mock.json` — 24 кейса через боевой вебхук, mock-режим | 2026-10-05 07:31 | 24/24 ответа HTTP 200 и по контракту; утечек контактов 0 (3 кейса с контактами); p50 задержки 276 мс; $0 |
| `2026-10-05-fake-api.json` — LLM-ветка против заглушки Messages API | 2026-10-05 07:06 | валидный ответ; повтор после битого JSON; `needs_human` после двух неудач, после HTTP 500 и при недоступном API; отказ 429 по дневному бюджету; тестовый ключ в sqlite и журналах не найден |

Точность mock-заглушки на тех же 24 кейсах: категория 20/24, срочность 12/12, город 18/18,
бюджет 14/14, `needs_human` 7/10. Это проверка проводки, а не качества: правила заглушки
и кейсы написал один автор, кейсов мало, и они синтетические. Для LLM эти числа
ничего не говорят.

Чтобы получить настоящие цифры, нужно добавить ключ и прогнать тот же набор
(см. ниже). Расход на 24 кейса по резерву cost guard — не больше $0.20, фактический
будет записан в файл результата.

## Запуск

Нужны сервер с Docker и доступ по ssh. n8n слушает только `127.0.0.1:18102`,
наружу ничего не открывается.

```bash
DEPLOY_HOST=vps scripts/deploy.sh
```

Скрипт проверяет сборку и тесты, копирует проект в `/opt/demos/n8n`, создаёт там `.env`
со случайными `N8N_ENCRYPTION_KEY`, солью для IP и токеном прогонов, импортирует
воркфлоу из `workflows/*.json` через `n8n import:workflow`, публикует их
`n8n publish:workflow`, запускает контейнер и делает smoke-проверку.
Повторный запуск безопасен: `.env` не перезаписывается, воркфлоу переимпортируются.

Открыть с рабочей машины:

```bash
ssh -L 18102:127.0.0.1:18102 vps
# форма:  http://localhost:18102/form/triage-demo
# доска:  http://localhost:18102/webhook/board
# редактор n8n: http://localhost:18102 (аккаунт владельца создаётся при первом входе)
curl -s -X POST http://localhost:18102/webhook/triage \
  -H 'Content-Type: application/json' \
  -d '{"text":"Сломался генератор на складе в Казани, нужен мастер сегодня"}'
```

Включить LLM: на сервере вписать ключ в `/opt/demos/n8n/.env` (`ANTHROPIC_API_KEY=...`),
затем `docker compose up -d` в той же папке. Проверить качество:

```bash
cd /opt/demos/n8n
python3 evals/run_evals.py --env-file .env --out evals/results/$(date -u +%F)-llm.json
```

Публичный адрес: обратный прокси на `127.0.0.1:18102`, который пробрасывает только
`/form/`, `/form-waiting/` и `/webhook/`, ставит `X-Real-IP`; в `.env` поменять
`WEBHOOK_URL` и раскомментировать `N8N_PROXY_HOPS=1`.

## Настройки (`.env`)

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `ANTHROPIC_API_KEY` | пусто | пусто = mock-режим |
| `LLM_MODEL` | `claude-haiku-4-5-20251001` | модель |
| `DAILY_BUDGET_USD` | `0.50` | дневной бюджет на LLM |
| `RATE_LIMIT_PER_IP_HOUR` | `5` | заявок в час с одного адреса |
| `RATE_LIMIT_GLOBAL_HOUR` | `60` | заявок в час всего |
| `PRICE_INPUT_USD_PER_MTOK` / `PRICE_OUTPUT_USD_PER_MTOK` | `1.00` / `5.00` | цена Haiku 4.5 за 1 млн токенов, сверить перед запуском |
| `TELEGRAM_CHAT_ID` | пусто | чат для уведомлений, когда нода будет включена |

## Структура

```
docker-compose.yml        n8n 2.41.6, sqlite в volume, 127.0.0.1:18102, mem_limit 600m
.env.example              шаблон; настоящий .env только на сервере
src/lib/*.js              маскирование, mock, контракт и проверка LLM, HTML
src/nodes/*.js            код Code-нод
scripts/build_workflows.py  собирает workflows/*.json из src/
workflows/*.json          вход (вебхук и форма), ядро, доска — импортируются CLI
scripts/deploy.sh         деплой; remote_deploy.sh и smoke.sh выполняются на сервере
tests/                    юнит-тесты, проверка JSON воркфлоу, заглушка Messages API
evals/                    24 кейса, раннер, результаты прогонов
docs/design.md            почему такие ноды, cost guard, маскирование, компромиссы
```

Локальные проверки: `node tests/test_lib.js`, `node tests/check_workflows.js`,
`python3 scripts/build_workflows.py --check`.

## Ограничения

- Лимит по IP работает только за обратным прокси; без него все запросы делят один ключ.
- Маскирование ловит типовые форматы телефонов, email, карт и ников. ФИО, адреса и номера,
  записанные словами, не ловит.
- Исполнения идут по одному (так cost guard не обходится параллельными запросами),
  поэтому под нагрузкой заявки ждут в очереди.
- Telegram-уведомление выключено до появления токена бота.
