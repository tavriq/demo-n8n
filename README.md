# Триаж входящих заявок на n8n под Claude Haiku 4.5

Клиент пишет заявку свободным текстом. n8n раскладывает её по полям (категория, срочность,
город, бюджет, суть, следующий шаг для менеджера), решает, нужен ли человек, и показывает
результат на публичной доске. Контакты в тексте скрываются до сохранения. Расход на модель
ограничен бюджетом в долларах на день.

**Статус на 2026-10-05.** Claude ещё ни разу не вызывался: ключа API нет. Работает
заглушка по ключевым словам (mock), все цифры ниже получены на ней и так помечены.
Качество модели не измерено. Проект собран за один день с Claude Code; что проверено
и чем, описано ниже со ссылками на файлы прогонов.

## Задача

Вымышленная сервисная компания: ремонт и аренда оборудования, уборка, консультации.
Менеджер читает каждую заявку с сайта и решает, кому её отдать и насколько она срочная.
Жалобы и спорные случаи теряются среди рекламы и вопросов «а вы работаете в выходные?».

Воркфлоу делает первичный разбор: раскладывает заявку по полям, предлагает следующий шаг,
а жалобы, неясные и срочные заявки отправляет менеджеру в Telegram (нода готова, но выключена
до появления токена бота). В форме одно поле, текст до 1000 символов. Имени, телефона и email
форма не спрашивает.

## Схема

```
 форма /form/triage-demo                    POST /webhook/triage (для evals, наружу не открыт)
            \______ под-воркфлоу «ядро» (оба входа ждут его ответ) ______/
                               |
   Подготовка: проверка текста, маскирование контактов, ключ клиента по IP, режим
   Журнал за 24 часа (Data Table) -> лимиты и бюджет --- нельзя ---> отказ 400 / 429
             | можно
   есть ключ API? -- нет --> заглушка по ключевым словам (mode=mock, $0)
             | да
   Claude #1 -> проверка ответа --не прошла--> Claude #2 -> проверка (снова нет: needs_human)
             |
   Итог: контакты в ответе модели скрываются ещё раз -> запись в журнал
             |                                   \--> нужен человек или срочно? -> Telegram (выкл.)
   ответ: JSON (API) или страница (форма)

 GET /webhook/board -> последние 20 заявок + «потрачено сегодня $X из $Y» -> HTML
```

Три воркфлоу лежат в `workflows/*.json` и импортируются через CLI n8n. Код Code-нод
хранится в `src/`, покрыт тестами и собирается в JSON скриптом `scripts/build_workflows.py`.
В ноде сначала идёт её собственный код, под ним нужные функции из `src/lib`. На холсте
у групп нод стоят заметки. Ноды по одной: `docs/design.md`.

## Ответ в JSON и его проверка

```json
{
  "category": "repair | rental | cleaning | consultation | complaint | spam | other",
  "urgency": "low | normal | high",
  "city": "Казань",
  "budget_rub": 15000,
  "summary": "до 20 слов",
  "next_step": "одна фраза менеджеру",
  "needs_human": false,
  "confidence": 0.92
}
```

- Запрос к Claude идёт с `output_config.format` типа `json_schema`: enum для категории
  и срочности, `null` для города и бюджета, `additionalProperties: false`.
- Схема не выражает «confidence от 0 до 1» и «не больше 20 слов». Это проверяет
  `validateTriage` (`src/lib/triage.js`). При нарушении запрос повторяется один раз
  со списком ошибок. После второй неудачи, ошибки HTTP или недоступного API заявка
  получает `needs_human=true` и всё равно сохраняется.
- Длинный `summary` обрезается до 20 слов без повторного запроса.
- `needs_human` ставит правило поверх ответа модели: жалоба, `confidence < 0.6`
  или контакт, который модель вписала в ответ.

## Защита

**Бюджет (cost guard).** Перед вызовом модели ядро суммирует расход за сегодня (по Москве)
из журнала и добавляет резерв на худший случай: две попытки, `max_tokens` на выходе.
Если сумма больше `DAILY_BUDGET_USD` ($0.50 по умолчанию), заявка получает 429 с текстом
«потрачено $X из $Y». Расход считается по `usage` из ответа API по ценам Haiku 4.5:
$1 за 1 млн входных токенов и $5 за 1 млн выходных. Исполнения идут строго по одному
(`N8N_CONCURRENCY_PRODUCTION_LIMIT=1`), поэтому параллельные заявки не проскочат
проверку до записи друг друга.

**Лимиты частоты.** 5 заявок в час с одного адреса; 60 в час через форму и отдельно 60
через API, чтобы скрипт, выбравший лимит API, не закрыл форму. Адрес клиента берётся
из заголовка, только если так задано в `TRUST_PROXY_HEADER`: по умолчанию заголовки
игнорируются, иначе клиент подставил бы свой `X-Real-IP` и обошёл лимит. В журнал
пишется HMAC адреса с солью, а не IP. Заголовок `X-Eval-Token` (секрет живёт только
в `.env` на сервере) снимает лимиты в час для прогонов evals и проверки после деплоя;
дневной бюджет он не снимает.

**Маскирование.** До сохранения и до отправки в модель `maskPII` заменяет на метки телефоны
(в том числе `(916)123-45-67`, `+7.916.123.45.67`, пробел между каждой цифрой), email
(в том числе `иван@почта.рф` и «собака/точка»), номера карт, паспорт, СНИЛС, ИНН, ссылки
`t.me`/`vk.com`/`wa.me` и ники. Бюджеты, диапазоны сумм, даты и IP не трогаются: это
закреплено тестами. Ответ модели (summary, next_step, city) проходит маскирование ещё раз:
если клиент записал телефон словами, модель могла переписать его цифрами.
Не ловится: телефон словами в самом тексте заявки, «ivan at mail dot ru» без скобок,
ник без @ и без слова вроде «tg:», адреса, ФИО. Поэтому форма просит не писать
персональные данные. Полный список: `docs/design.md`.

**Публичная доска.** Весь текст пользователя и модели экранируется. Скриптов и внешних
ресурсов нет, в `<meta>` стоит CSP `default-src 'none'; style-src 'unsafe-inline'`
(встроенные стили разрешены). Текст спама, жалоб, неясных заявок и заявок с грубой
лексикой на доске не показывается: только метки и причина. Заявку при этом принимают
и разбирают, её видит менеджер.

**Prompt injection.** Текст заявки передаётся внутри тега `<заявка>`; такие теги внутри
текста клиента вырезаются, чтобы он не мог «закрыть» заявку и дописать свои правила.
Системный промпт называет текст данными, а не инструкциями. Если модель поддастся,
ответ всё равно ограничен схемой и проверкой: у воркфлоу нет инструментов и действий,
худший исход — неверная метка. Жалобе `needs_human=true` ставит правило. Если же модель
сменила категорию, правило не поможет; этот случай проверяет кейс `injection-hide-complaint`.

**Размер запроса и боты.** JSON до 1 МБ, файлы в multipart до 1 МБ
(`N8N_FORMDATA_FILE_SIZE_MAX`, по умолчанию в n8n было 200 МБ): файл 2 МБ получает 413.
Текстовые поля multipart n8n этой настройкой не ограничивает, нужен лимит на прокси
(`client_max_body_size 16k` в `docs/nginx.conf.example`). Форма отвечает 401 на запросы
без браузерного User-Agent. Вебхук `/triage` разрешает CORS только origin туннеля.

## Метрики

Только то, что реально прогонялось. Режим и дата указаны у каждой строки.

| Прогон | Дата (UTC) | Режим | Результат |
|---|---|---|---|
| `evals/checks-2026-10-05.json` — проверки защиты на живом сервере, 3 фазы | 2026-10-05 08:24 | mock + заглушка API | 8 групп из 8 прошли, подробности ниже |
| `evals/results-2026-10-05-mock.json` — 42 кейса через вебхук, отчёт `evals/latest.md` | 2026-10-05 08:25 | mock | контакты скрыты 5/5, ошибок сервера 0, задержка p50 311 мс и p95 484 мс, $0 |
| Claude Haiku 4.5 на тех же 42 кейсах | — | live | **не прогонялось: нужен ключ API** |

Задержка измерена на заглушке; сколько занимает разбор моделью, неизвестно.

**Проверки защиты** (`evals/checks.py`). Фаза 1 на текущих настройках, фаза 2 с временным
`TRUST_PROXY_HEADER=x-real-ip`, фаза 3 с временной заглушкой Messages API вместо Anthropic.
После фаз 2 и 3 скрипт вернул `.env` байт в байт.

- XSS: заявка с `<script>` и `<img onerror>` на доске показана текстом, тегов нет.
- Маскирование: 6 контактов в одной заявке (`+7 916 …`, `(495)…`, два email, ник, `t.me/…`)
  скрыты в ответе, в сохранённом тексте и на доске.
- Файл 2 МБ в multipart на `/webhook/triage` получил 413.
- Подделка адреса: при настройке по умолчанию 3 заявки прошли, четвёртая получила 429,
  хотя у каждой был свой `X-Real-IP`. Лимит 5, но две заявки с этого ключа уже были за час.
- Лимит по адресу (фаза 2): 5 заявок через API приняты, шестая 429; другой адрес прошёл.
  То же через форму: 5 приняты, шестая получила страницу «Заявка не принята».
- Форма (фаза 2): `curl` получает 401 на GET и POST; на странице результата HTML из заявки
  показан текстом, без двойного экранирования, телефон скрыт.
- Ветка модели на заглушке API (фаза 3): HTTP 500 дважды → `needs_human`, $0; битый JSON
  один раз → повтор, 2 попытки; дважды → `category=other`, `needs_human`; заглушка вписала
  телефон и email в ответ → они скрыты, `needs_human=true`. Затем следующая заявка получила
  429 `daily_budget`, хотя у неё был токен прогонов. В заглушку ушло ровно 7 запросов,
  ни в одном нет телефона или email. Тестового ключа API нет ни в sqlite n8n, ни в логах.
- Память контейнера: 379 МиБ до проверок, 482 МиБ после, лимит 600 МиБ.

На доске за 2026-10-05 числится $0.0077: это `usage` заглушки API из двух запусков
`checks.py` (07:51 и 08:24 UTC). Настоящих денег не потрачено.

**42 кейса на заглушке.** Это проверка, что весь путь от вебхука до журнала работает,
а не оценка качества. Заглушка ищет ключевые слова; её правила и разметку писал один автор.
Ответ по контракту 42/42 у заглушки гарантирован её кодом. Инструкции в тексте она не читает,
поэтому 4/4 по prompt injection ничего не говорят об устойчивости модели. Для справки:
категория 26/42 (62%) против 26% у правила «всегда самый частый класс», срочность 34/42,
recall по `needs_human` 5/8. По точности `needs_human` заглушка хуже правила «никогда
не звать человека»: 71% против 81%. Полный отчёт с матрицами ошибок: `evals/latest.md`.

Набор уже ловит настоящие ошибки заглушки: «долгосрочная аренда» получила высокую срочность
(внутри слова есть «срочн»), а «бюджет 15-20 тыс» превратился в 15 рублей. Заглушку под кейсы
не подгонял: её задача — проверять путь заявки без денег, а подогнанная под 42 кейса
заглушка показывала бы точность, которой нет.

**Разметка** (`evals/cases.jsonl`, 42 кейса): опечатки и разговорный стиль, смешанные
запросы, 5 жалоб, 5 спама, 6 заявок с контактами (одна с телефоном словами), 4 попытки
prompt injection. Для спорных случаев указан список допустимых меток, первая основная;
точность считается строго и с учётом допустимых. Ответы без HTTP 200 считаются ошибками
сервера и в точность не входят. `python3 evals/run.py --self-test` проверяет сам подсчёт
без сети: ответ, равный разметке, обязан набрать 100%, константа — ровно уровень правила
«самый частый класс», HTTP 500 — попасть в ошибки сервера. Этот тест входит в `scripts/deploy.sh`.

История разметки, чтобы её можно было проверить по git:

- 40 кейсов зафиксированы в `d49c5a4` до прогона этих 40. Первым прогоном это не было:
  в `2d691f9` заглушка уже прошла набор из 24 кейсов. 6 текстов оттуда вошли в новый набор
  дословно, большинство остальных переписаны.
- Подгонки меток под заглушку нет: sha256 разметки в результатах (`8a0d67f28152`) совпадал
  с `d49c5a4`, `src/lib/mock.js` не менялся после `e7d34dc`, а из меток, которые появились
  или поменялись после первого прогона, пять расходятся с ответом заглушки.
- До первого прогона на модели разметка поправлена ещё раз отдельным коммитом `2117628`
  (причина каждой правки в сообщении) и добавлены 2 кейса. После прогона на модели метки
  не трогаются. Дельта на заглушке: только два новых кейса, оба верно.
- Все коммиты сделаны 2026-10-05 пачками, поэтому порядок коммитов слабое доказательство.
  Опирайтесь на `cases_sha256` и `date_utc` в файлах результатов.

## Подключить ключ API

Прогон запускается с рабочей машины через туннель: результаты сразу пишутся в локальный
репозиторий, а деплой их не сотрёт.

```bash
ssh -t vps nano /opt/demos/n8n/.env       # ANTHROPIC_API_KEY=...
ssh vps 'cd /opt/demos/n8n && docker compose up -d --wait n8n && python3 scripts/wait_published.py'
ssh -f -N -L 18102:127.0.0.1:18102 vps
export EVAL_BYPASS_TOKEN=$(ssh vps "grep -E '^EVAL_BYPASS_TOKEN=' /opt/demos/n8n/.env | cut -d= -f2-")
python3 evals/run.py --base http://localhost:18102   # -> evals/results-<дата>-llm.json, evals/latest.md
```

Оценка сверху для 42 кейсов: резерв на заявку около $0.008 (две попытки, полный
`max_tokens`), то есть до $0.34. Фактический расход запишется в файл результата.
Дневной бюджет $0.50 общий для прогона и посетителей формы.

`evals/checks.py` при заданном ключе пропускает фазу 3, чтобы не тратить деньги
и не трогать ключ. Фазы 1 и 2 работают в любом режиме.

## Подключить Telegram

Нода «Telegram менеджеру» выключена. Уведомление уходит после записи заявки в журнал,
когда `needs_human=true` или срочность высокая. Сбой Telegram не ломает приём заявки:
у ноды `onError: continueRegularOutput`. Текст экранируется под `parse_mode=HTML`.

1. Создать бота у @BotFather и узнать id чата менеджера.
2. В редакторе n8n (через ssh-туннель, см. ниже) создать credential «Telegram API»
   с токеном бота. Токен хранится в n8n зашифрованным и в git не попадает.
3. В `scripts/build_workflows.py` у ноды «Telegram менеджеру» убрать `disabled=True`
   и добавить `credentials={"telegramApi": {"id": "<id credential>", "name": "<имя>"}}`.
   Пересобрать: `python3 scripts/build_workflows.py`.
4. В `.env` на сервере вписать `TELEGRAM_CHAT_ID`, затем запустить `scripts/deploy.sh`.

Включать ноду только в редакторе бесполезно: следующий деплой переимпортирует
воркфлоу из git.

## Развернуть

Нужен сервер с Docker и доступ по ssh. n8n слушает только `127.0.0.1:18102`,
наружу ничего не открывается.

```bash
DEPLOY_HOST=vps scripts/deploy.sh
```

Скрипт проверяет сборку, тесты и подсчёт evals, копирует проект в `/opt/demos/n8n`
(результаты прогонов на сервере не трогает), создаёт там `.env` со случайными
`N8N_ENCRYPTION_KEY`, солью для IP и токеном прогонов (существующий `.env` не перезаписывается,
новые ключи дописываются), импортирует воркфлоу через `n8n import:workflow`, публикует
`n8n publish:workflow`, запускает контейнер, ждёт, пока n8n применит публикацию,
и отправляет пробную заявку. Повторный запуск безопасен.

Открыть с рабочей машины:

```bash
ssh -L 18102:127.0.0.1:18102 vps
# форма:  http://localhost:18102/form/triage-demo
# доска:  http://localhost:18102/webhook/board
# редактор: http://localhost:18102
```

Аккаунт владельца n8n ещё не создан: первый, кто откроет редактор, станет владельцем
и через `$env` увидит секреты из `.env`. Создать его через туннель до того, как что-то
публиковать.

**Публичный адрес.** Пример nginx: `docs/nginx.conf.example` (не применялся). Наружу
только `/form/`, `/form-waiting/` и `/webhook/board`; `/webhook/triage` и редактор не
публикуются. Прокси перезаписывает `X-Real-IP`, ограничивает частоту (`limit_req`),
число соединений и размер тела, кэширует доску на 20 секунд. Без этого доска и общая
очередь исполнений — точка отказа: каждый GET доски ждёт своей очереди вместе с заявками.
В `.env`: `TRUST_PROXY_HEADER=x-real-ip`, публичный `WEBHOOK_URL`, `N8N_PROXY_HOPS=1`.
Caddy и Cloudflare Tunnel не перезаписывают `X-Real-IP` клиента; для Cloudflare нужен
`cf-connecting-ip`.

Прогоны на сервере: `python3 evals/checks.py` (затем забрать результат:
`rsync -av vps:/opt/demos/n8n/evals/ ./evals/ --include='checks-*' --include='results-*' --include='latest.md' --exclude='*'`).
Локальные проверки: `node tests/test_lib.js`, `node tests/test_nodes.js`,
`node tests/check_workflows.js`, `python3 scripts/build_workflows.py --check`.

## Ограничения и что дальше

- Качество Claude не измерено. Первый шаг после появления ключа: прогон `evals/run.py`
  на тех же 42 кейсах и сравнение с заглушкой в `evals/latest.md`.
- 42 синтетических кейса и один автор разметки. 95% доверительный интервал около
  ±15 п.п., разницу меньше этого считать шумом. Для решений нужны 150–200 реальных
  обезличенных заявок и второй разметчик.
- Без прокси лимит по адресу не различает клиентов: все делят ключ `direct` и 5 заявок в час.
- Маскирование построено на регулярных выражениях (что не ловится, см. «Защита»).
- Заявки обрабатываются по одной. Так бюджет не обходится параллельными запросами,
  но под нагрузкой заявки и доска ждут в очереди.
- Скриншота холста n8n нет: для него нужен аккаунт владельца, его создаёт владелец сервера.
- Страница формы — шаблон n8n, она подгружает шрифт с Google Fonts. Доска внешних
  ресурсов не использует.
